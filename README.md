# FOSSiBOT Power Station — інтеграція для Home Assistant

Custom component для хмарного API `app.fossibot.hk` (застосунок Fossibot+).
Реалізовано REST-логін, автовиявлення пристроїв та WebSocket-телеметрію
(sensor + binary_sensor). Керування (switch) — наступний етап.

Репозиторій: <https://github.com/zelin-sky/ha-fossibot-plus>
Домен інтеграції: `fossibot_plus` (навмисно з суфіксом `_plus`, щоб не
перетинатись з іншими Fossibot-інтеграціями в HACS/HA).

## Встановлення через HACS

Репозиторій вже має структуру, потрібну HACS (`hacs.json` у корені,
`custom_components/fossibot_plus/` з `manifest.json`, що містить `domain`,
`name`, `version`, `documentation`, `issue_tracker`, `codeowners`).

1. Створіть публічний репозиторій `zelin-sky/ha-fossibot-plus` на GitHub
   і запуште туди вміст цього архіву як є (корінь репозиторію = корінь
   архіву: `README.md`, `hacs.json`, `custom_components/`).
2. `manifest.json` уже посилається на
   `https://github.com/zelin-sky/ha-fossibot-plus` — окремо нічого
   змінювати не треба, якщо назва репозиторію саме така.
3. (Рекомендовано, не обов'язково) Опублікуйте GitHub Release з тегом,
   що збігається з `version` у `manifest.json` (наприклад `v0.1.0`) —
   тоді HACS показуватиме історію версій; без релізів HACS просто бере
   файли з дефолтної гілки.
4. На репозиторії GitHub задайте короткий опис (Description) — HACS
   показує його в UI — і додайте хоча б один topic.
5. У Home Assistant: HACS → три крапки праворуч зверху → **Custom
   repositories** → вставте `https://github.com/zelin-sky/ha-fossibot-plus`,
   категорія **Integration**.
6. Знайдіть "FOSSiBOT Power Station" у списку HACS → Download.
7. Перезапустіть Home Assistant, далі — як у розділі нижче (Налаштування
   → Пристрої та служби → Додати інтеграцію → FOSSiBOT).

Без власного репозиторію на GitHub HACS працювати не буде — це головна
умова: HACS тягне файли з git-репозиторію, а не приймає ZIP напряму (крім
разового ручного встановлення нижче).

## Встановлення вручну (без HACS)

1. Скопіюйте `custom_components/fossibot_plus/` у
   `<config>/custom_components/`.
2. Перезапустіть Home Assistant.
3. Налаштування → Пристрої та служби → Додати інтеграцію → FOSSiBOT.
4. Введіть email/пароль від застосунку Fossibot+.

## Що виправлено відносно вихідного документа

1. **Код `api.py`/`config_flow.py` у вихідному файлі був пошкоджений** —
   рядки коду виявились переплутані (схоже, впорядковані за алфавітом) і
   не є валідним Python. Обидва файли переписані з нуля на основі опису
   REST/WS-контракту з розділів 2–3 документа.
2. **Тег `0500` — не єдине `uint32`.** У прикладі кадру (`28012610`) як
   uint32 LE це дало б безглузде число; насправді туди запаковано два
   16-бітних значення (`0x0128`=296 та `0x1026`=4134, збігається з нотатками
   документа "Основне значення"). Реалізовано розбиття на два слова
   (`sub_word=0/1` у `sensor.py`), обидва сенсори вимкнені за замовчуванням,
   поки їхній фізичний сенс не підтверджено на реальному пристрої.
3. **Тег `2a00` описано подвійно** ("напруга / струм") без коефіцієнта
   масштабування — виведено як сире, вимкнене за замовчуванням значення,
   а не видано за конкретну одиницю виміру.
4. **Таблиця тегів у документі мала повторюваний артефакт** — до кожного
   опису була приліплена фраза "Невідомо" (найімовірніше, зсув колонок при
   форматуванні markdown-таблиці). Прибрано з коду/коментарів.
5. **`manifest.json`**: прибрано зайву залежність `"requirements": ["aiohttp"]`
   — цей пакет уже вбудований у Home Assistant Core, і його явне зазначення
   в custom component зазвичай не потрібне і може конфліктувати з версією
   з ядра. Додано `"integration_type": "hub"`.
6. **Життєвий цикл aiohttp-сесії**: чернетка створювала власний
   `aiohttp.ClientSession`. Тепер використовується спільна сесія HA
   (`async_get_clientsession`), щоб уникнути витоку з'єднань при
   перезавантаженні запису конфігурації.
7. **Обробка розриву WebSocket**: у документі описано лише щасливий шлях
   (heartbeat кожні 5с). Оскільки нічого не сказано про поведінку при
   розриві з'єднання, додано цикл перепідключення з фіксованою затримкою
   (`RECONNECT_DELAY`).
8. **Прострочення токена**: документ не описує оновлення JWT. Додано
   одноразовий повторний логін при відповіді `401` від `user_device/list`.
9. **CRC16 у хвості кадру** парситься (відсікається), але не перевіряється —
   алгоритм контрольної суми в документі не наведено; позначено як TODO
   в коментарях `api.py`.
10. Додано `hacs.json` у корені репозиторію та ключ `issue_tracker` у
    `manifest.json` — обидва обов'язкові для HACS (`domain`, `documentation`,
    `issue_tracker`, `codeowners`, `name`, `version` — усі присутні).
11. Стан `2700` (головне живлення) та `2b00` (реле AC) — справжні
    булеві прапорці (0/1), винесені в `binary_sensor`. Стани `2c00`/`2d00`
    (DC/USB) у прикладі мають значення `2`, тобто це не проста булева
    величина, а маска/режим — залишено як числовий `sensor`, а не
    `binary_sensor`.
12. **Схема з'єднання: `http`, а не `https`.** Специфікація стверджувала
    `https://app.fossibot.hk`, але захоплення трафіку реального застосунку
    (Charles) показало звичайний HTTP на порту 80 (`SSL: -`). Саме це було
    причиною помилки "Не вдалося з'єднатися" — HA намагався зробити TLS-
    хендшейк там, де сервер його не очікує. `BASE_URL` виправлено на
    `http://...`. За аналогією `WS_URL` теж змінено на `ws://` (поки не
    підтверджено окремим захопленням саме WS-рукостискання).
13. **Захист від дубльованих запитів на бекенді.** Сервер (схоже, на
    RuoYi-подібному фреймворку) відхиляє повторний ідентичний логін-запит,
    надісланий за кілька секунд після попереднього, повідомленням
    `"不允许重复提交，请稍候再试"` — це трапляється на практиці, бо конфіг-
    флоу вже робить один логін для перевірки пароля, а `async_setup_entry`
    одразу після створення запису робить другий, новим клієнтом. Це не
    помилка пароля — додано ретрай (`LOGIN_MAX_RETRIES`, `LOGIN_RETRY_DELAY`
    у `const.py`): при виявленні саме цього повідомлення `async_login`
    чекає кілька секунд і повторює спробу, замість негайного провалу.

## Перевірка парсера

`parse_payload()` протестовано на прикладі кадру з документа (36 блоків
tag+value + CRC-хвіст) — усі очікувані значення (814 Вт, 13 °C, 50.0 Гц,
296/4134 для батарейного тега тощо) збігаються.

## Далі

- Додати `switch.py` для керування AC/DC/USB виходами (окремий етап,
  за задумом користувача).
